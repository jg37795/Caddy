# GROK BRIEF — Auto-detect golf putting green from LiDAR + satellite

## Your task

Write ONE pure JavaScript function, `detectGreen(data)`, that finds the
putting-green boundary near the centre of a golf-hole dataset and returns
its polygon. This will run inside an existing golf app (Caddy) as the
"drop a pin → get the green" feature.

## Input — `data` (exactly this shape, no other keys guaranteed)

```js
{
  grid: {
    W: 96, H: 96, cellSizeM: 3.125,
    // each feature is a Float64Array of W*H cells (row-major, index=y*W+x);
    // NaN = no data. Cells are in LOCAL METRES: x = (i%W - W/2)*cellSizeM
    // (east+), y = (H/2 - floor(i/W))*cellSizeM (north+). Origin = the
    // pin the user dropped (the green is near the origin — within ~100 m).
    z:       Float64Array,  // elevation, metres (LiDAR 3DEP 1m, resampled)
    slope:   Float64Array,  // % slope per cell
    smooth3: Float64Array,  // elevation std-dev in 3x3 (m) — LOW on greens
    tex5:    Float64Array,  // slope std-dev in 5x5 — LOW on greens
    exg:     Float64Array,  // excess-green from satellite: 2G-R-B (can be neg)
    bright:  Float64Array   // satellite brightness 0..255
  },
  // satellite sample helper: returns {r,g,b} 0..255 at lon/lat, or null
  satSample: (lon, lat) => ({r,g,b}) | null
}
```

## Output

```js
{
  poly: [[mx,my], ...],  // 8..64 points, LOCAL METRES, same frame as above
  confidence: 0..1       // your honest confidence the polygon IS a green
}
```
or `null` when you cannot find a green with confidence >= 0.5.

## Physical facts to exploit

- Putting greens are mowed daily: **lowest height variance** of any turf
  (smooth3 is very low), **low slope** (< ~5% mostly), and their slope
  TEXTURE (tex5) is far smoother than fairway.
- Greens sit inside a slightly raised or flat "collar" then drop to fairway.
- In satellite imagery, greens read as **uniform, medium-bright, high
  excess-green** patches with hard edges against darker/patchier fairway.
- Typical green size: **300–900 m²** (perimeter ~70–130 m). Reject blobs
  smaller than ~150 m² or larger than ~2500 m².
- There may be MULTIPLE greens in the grid — pick the one containing or
  nearest the origin (0,0). Reject candidates whose centroid is >120 m
  from the origin.
- Data quirks: NaN cells exist (LiDAR dropouts); exg/bright may be NaN
  where the satellite was cloudy — tolerate missing satellite data
  (LiDAR alone must still work, at lower confidence).

## Algorithm guidance (you choose the details)

Suggested skeleton — segment on a score, clean up, extract boundary:
1. Per-cell green-ness score combining: low smooth3 (strongest signal),
   low tex5, low slope, high exg, moderate bright (not pavement-bright).
2. Threshold + morphological cleanup (erode/dilate to kill speckle).
3. Connected components; pick the component containing/near (0,0).
4. Trace the boundary (marching squares or convex-hull-of-component then
   simplify with Douglas-Peucker to 8..64 points).
5. Confidence = how well size/shape/texture statistics match the expected
   green profile. Be honest — 0.9 for textbook greens, 0.5 for marginal.

## Quality bar (we will test against labeled ground truth)

Two real sites (Iowa golf course, winter aerial — muted colors):
- siteA: OSM-verified green, IoU target >= 0.75
- siteB: hand-traced green (irregular heart shape), IoU target >= 0.70
A wrong polygon that looks plausible is WORSE than `null` — when unsure,
return null. The caller falls back to manual tracing.
